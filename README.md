## Возможности

- Защита от массовых действий: удаление и создание каналов, удаление и создание ролей, баны, запрещённые пинги.
- Защита от выдачи и снятия ролей, а также от выдачи роли с правами администратора.
- Автоматический откат: удалённые каналы и роли создаются заново, лишние каналы и роли удаляются, забаненные участники разбанятся.
- Гибкие лимиты для каждой группы (роли или конкретного пользователя): действие можно разрешить, запретить или разрешить ограниченное число раз.
- Система предупреждений: счётчик нарушений у каждого участника, который сам уменьшается со временем.
- Карантин: у нарушителя снимаются все роли, ему выдаётся роль карантина, а администраторы могут вернуть всё одной кнопкой.
- Автоматический кик ботов, которые добавлены на сервер без разрешения или совершили опасное действие.
- Белый список: доверенные пользователи полностью исключаются из проверок.
- Управление через слэш-команды и интерактивное меню с выпадающими списками и кнопками.
- Уведомления в канал предупреждений и канал карантина, а также личное сообщение нарушителю.

## Как это работает

Бот слушает события сервера и проверяет по журналу аудита, кто их совершил. Дальше решение зависит от настроек группы нарушителя.

| Значение функции | Что делает бот |
|------------------|----------------|
| `Разрешено` | Действие игнорируется |
| `Запрещено` | Нарушитель сразу уходит в карантин |
| Число `N` | Первые `N - 1` действий дают предупреждение, `N`-е действие приводит к карантину |

Если у участника нет подходящей группы, действие считается запрещённым. При создании новой группы все функции стоят в значении `Запрещено`.

Что происходит при срабатывании защиты:

1. Опасное действие откатывается (канал или роль восстанавливаются, лишнее удаляется, бан снимается).
2. Если нарушитель бот, он кикается.
3. С нарушителя снимаются все роли. Список ролей сохраняется в базе.
4. В канал карантина уходит сообщение со списком снятых ролей и кнопкой «Восстановить».
5. Нарушителю выдаётся роль карантина и приходит личное сообщение.

Счётчик предупреждений уменьшается на 1 каждые 120 секунд.

### Отслеживаемые события

| Событие | Функция в настройках | Реакция |
|---------|----------------------|---------|
| Сообщение с `@everyone` / `@here` | `ping_anti_crash` | Сообщение удаляется, вебхук тоже, нарушитель в карантин |
| Бан участника | `ban_anti_crash` | Участник разбанивается, нарушитель в карантин |
| Удаление канала | `delete_channels_anti_crash` | Канал создаётся заново вместе с правами |
| Создание канала | `create_channels_anti_crash` | Канал удаляется |
| Удаление роли | `role_delete_anti_crash` | Роль создаётся заново с теми же правами и позицией |
| Создание роли | `create_role_anti_crash` | Роль удаляется |
| Роли выдаётся право администратора | `role_create_admin_anti_crash` | Права роли возвращаются |
| Выдача или снятие роли | `give_role_anti_crash` | Роль у участника убирается обратно |
| Выдача роли с правами администратора | `give_role_admin_anti_crash` | То же, но строже |
| Вход бота на сервер | белый список, поле `check` | Бот кикается |

## Требования

- Python 3.10 или новее (в коде используется `match`).
- Аккаунт и кластер MongoDB (подойдёт бесплатный MongoDB Atlas или локальный сервер).
- Бот, созданный в [Discord Developer Portal](https://discord.com/developers/applications).

Библиотеки:

```
disnake
pymongo
dnspython
```

`dnspython` нужен для подключения по адресу вида `mongodb+srv://`.

## Установка

**1. Скачай проект и перейди в папку**

```bash
cd "Антикраш VTOP"
```

**2. Создай виртуальное окружение (по желанию)**

```bash
python -m venv venv

# Linux / macOS
source venv/bin/activate

# Windows
venv\Scripts\activate
```

**3. Установи зависимости**

```bash
pip install disnake pymongo dnspython
```

**4. Создай и настрой бота в Discord**

1. В Developer Portal создай приложение и добавь к нему бота, скопируй токен.
2. На вкладке **Bot** включи привилегированные интенты: **Server Members Intent** и **Message Content Intent**. Бот запускается со всеми интентами.
3. Пригласи бота на сервер с правами **Administrator**. Если нужен минимум, выдай: Manage Roles, Manage Channels, Kick Members, Ban Members, View Audit Log, Manage Webhooks, Manage Messages.
4. В настройках сервера подними роль бота **выше** всех ролей, которыми он должен управлять.

## Настройка

### 1. Файл `configs/days.json`

```json
{
    "mongodb_connect": "mongodb+srv://ПОЛЬЗОВАТЕЛЬ:ПАРОЛЬ@КЛАСТЕР.mongodb.net/?retryWrites=true&w=majority",
    "author": 123456789012345678,
    "quarantine_channel": 123456789012345678,
    "pred_channel": 123456789012345678,
    "whitelist": [123456789012345678]
}
```

| Поле | Описание |
|------|----------|
| `mongodb_connect` | Строка подключения к MongoDB |
| `author` | ID владельца бота |
| `quarantine_channel` | ID канала, куда приходят отчёты о карантине с кнопкой восстановления |
| `pred_channel` | ID канала для предупреждений |
| `whitelist` | ID пользователей, которым разрешено управлять ботом через команды |

### 2. Токен бота

В исходном коде токен записан прямо в `main.py` в последней строке (`bot.run(...)`). Так хранить его нельзя. Вынеси его в переменную окружения:

```python
import os

bot.run(os.environ["DISCORD_TOKEN"])
```

Запуск с переменной:

```bash
# Linux / macOS
export DISCORD_TOKEN="твой_токен"

# Windows (PowerShell)
$env:DISCORD_TOKEN="твой_токен"
```

### 3. Замена ID в коде

В коде жёстко прописаны ID конкретных серверов, ролей и пользователей. Перед запуском на своём сервере замени их (удобнее всего поиском по проекту).

| Что искать | Что это | Где |
|------------|---------|-----|
| `1189818907419222056` | ID основного сервера. В `main.py` это же число проверяется как ID владельца для команд `load`, `unload`, `reload` и указано в `test_guilds` | `main.py`, `anticrash.py` |
| `1071173859455279114` | ID владельца, которого бот никогда не наказывает | `anticrash.py` |
| `1189866428870967317` | ID роли карантина | `anticrash.py` |
| `982757267923406858` | ID второго сервера, по нему читается запись белого списка при смене ролей | `anticrash.py` |
| `1122980961559261284` | ID роли в служебном обработчике `xyesos` (его можно удалить) | `anticrash.py` |

В `main.py` также задан `test_guilds=[...]`. Укажи там ID своего сервера, иначе слэш-команды не появятся.

### 4. Подготовка базы данных

Бот использует базу `days`. Перед первым запуском нужно создать запись белого списка для сервера. Выполни один раз:

```python
import pymongo

cluster = pymongo.MongoClient("СТРОКА_ПОДКЛЮЧЕНИЯ")

cluster.days.whitelist.insert_one({
    "_id": "ID_СЕРВЕРА",          # строкой, тот же ID, что вписан в код
    "whitelist": [123456789012345678],   # ID доверенных пользователей
    "check": "NO"                 # "OK" разрешает входить любым ботам
})
```

Если сервер в коде заменён на несколько ID, создай такую запись для каждого.

## Управление ботом

Командами могут пользоваться только пользователи из `whitelist` в `configs/days.json`.

### Слэш-команды

| Команда | Параметр | Описание |
|---------|----------|----------|
| `/anticrash_manage` | нет | Открывает меню настройки групп |
| `/anticrash_group_add` | `group_role` (роль) | Создаёт группу для роли, все функции по умолчанию запрещены |
| `/anticrash_group_delete` | `group_role` (роль) | Удаляет группу роли |
| `/anticrash_user_add` | `group_role` (участник) | Создаёт группу для конкретного пользователя |
| `/anticrash_user_delete` | `group_role` (участник) | Удаляет группу пользователя |
| `/whitelist` | `пользователь` | Добавляет в белый список или убирает из него |

### Префиксные команды (только владелец)

Префикс: `anticrash!` или упоминание бота.

| Команда | Описание |
|---------|----------|
| `anticrash!load <модуль>` | Загрузить модуль |
| `anticrash!unload <модуль>` | Выгрузить модуль |
| `anticrash!reload <модуль>` | Перезагрузить модуль (имя без `.py`, например `anticrash`) |

### Настройка прав группы

1. Создай группу: `/anticrash_group_add @Роль`.
2. Открой меню: `/anticrash_manage`.
3. Выбери группу в выпадающем списке.
4. Выбери функцию, например «Удаление каналов».
5. Нажми нужную кнопку: разрешить, запретить или задать число, после чего отправь число в чат (на ответ даётся 180 секунд).

Для доверенных администраторов лучше использовать `/whitelist`, тогда они вообще не проверяются.

### Восстановление после карантина

В канале карантина под отчётом есть кнопка **«Восстановить»**. Она возвращает участнику все снятые роли, сбрасывает его счётчик предупреждений и убирает роль карантина.

## База данных

Используется база `days`.

| Коллекция | Назначение | Структура |
|-----------|-----------|-----------|
| `anti_crash` | Настройки групп | `_id` (ID роли или пользователя), далее по одному полю на функцию со значением `Разрешено`, `Запрещено` или числом |
| `anticrash` | Счётчики нарушений | `_id` (ID пользователя), `quarantine` (число предупреждений) |
| `whitelist` | Белые списки серверов | `_id` (ID сервера), `whitelist` (список ID), `check` (`OK` или другое значение) |
| `backup` | Резервные копии ролей | `_id` (ID пользователя) со списком `roles`, а также `_id` (ID сообщения карантина) с полем `quarantine` |

## Безопасность

- Не публикуй проект с настоящими данными. Токен бота и строка подключения к MongoDB в исходном архиве записаны открытым текстом (в `main.py` и `configs/days.json`). Если архив или репозиторий кто-то видел, **перевыпусти токен** в Developer Portal (кнопка Reset Token) и **смени пароль пользователя** в MongoDB.
- Добавь в `.gitignore`:

```
configs/days.json
__pycache__/
*.pyc
venv/
.env
```

- Ограничь доступ к кластеру MongoDB по IP, если это возможно.
- Выдавай права в `whitelist` в `days.json` только тем, кому доверяешь полностью: эти пользователи могут менять любые настройки защиты.

## Известные ограничения

Это заметки о текущем состоянии кода, а не инструкция по использованию.

- Функции `add_bot_anti_crash`, `edit_channels_anti_crash`, `unrole_anti_crash`, `unban_anti_crash`, `kick_anti_crash` и `time_out_anti_crash` есть в меню настройки, но отдельных обработчиков событий для них в коде нет.
- В обработчике `on_message` в списке запрещённых слов, помимо `@everyone` и `@here`, стоит слово `test`. Из-за этого сообщения со словом «test» тоже считаются нарушением. Удали его из списка.
- В кнопке «Восстановить» условие проверки прав записано с ошибкой (`role.id in inter.author.id in ...`), из-за чего кнопка может не срабатывать. Условие стоит переписать на `inter.author.id in config['whitelist']`.
- Бот читает записи белого списка по жёстко заданным ID серверов. Если такой записи в базе нет, обработчики событий падают с ошибкой.
- Сообщения в личные чаты вызывают ошибку в `on_message`, так как код обращается к `message.guild`.
- Папка `__pycache__` в архиве лишняя, её можно удалить.

## Частые проблемы

| Проблема | Решение |
|----------|---------|
| Слэш-команды не появляются | Проверь `test_guilds` в `main.py` и что бот приглашён с правами создавать команды |
| `FileNotFoundError: configs/days.json` | Запускай `python main.py` из папки проекта |
| `ServerSelectionTimeoutError` | Проверь строку подключения, пароль и доступ по IP в MongoDB Atlas |
| Бот не снимает роли и не кикает | Подними роль бота выше остальных и проверь права |
| `TypeError: 'NoneType' object is not subscriptable` в событиях | Не создана запись в коллекции `whitelist` для нужного сервера |
| Бот не видит участников или сообщения | Включи Server Members Intent и Message Content Intent |
| `PrivilegedIntentsRequired` | Привилегированные интенты не включены в Developer Portal |
